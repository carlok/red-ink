# Rules for agents working in this repo

This is Sublevel Three, a single-file browser fighting game (`index.html`, Babylon.js, Apache-2.0). `CONTINUE.md` explains how a sprint works and what has been built; `BACKLOG.md` holds the ranked ideas; `TUNING_LOG.md` records every measured change. Read `CONTINUE.md` before changing the game. This file is the short list of rules that a background agent or a new contributor must not break.

## What is where

- The game is `index.html`. There is no build step to play it. Do not split it into modules.
- `lib/babylon.js` is generated by `npm run build:engine` from the pinned Babylon.js packages. Never edit it by hand, and do not bump `@babylonjs/*` or `esbuild`: a new engine version has to be re-measured against the bout table in a sprint of its own (Dependabot is told to skip them).
- `assets/` and `audio/` hold fonts, one fighter model and CC0 sounds. Do not add synthetic voices, and do not touch the licence files (`LICENSE`, `NOTICE`, `audio/CC0.txt`, `assets/fonts/README.txt`, `assets/voice/README.txt`). Recordings in `assets/voice/` belong to whoever made them.
- Tests and probes live in `tools/`. `window.__sublevel` is the hook object they use.

## The numbers that must not move

The bout table is the balance contract. After any change that could touch the sim, run

```bash
node tools/balance-run.mjs 200 normal 1 normal 0-5
```

and expect 90.5 / 67.5 / 44.0 / 36.0 / 30.0 / 22.0. Render-only code (camera, particles, sound, DOM) must not touch the fixed 1/60 s sim or `rng()`. If a table value changes, the change is a balance change: say so, measure it and log it in `TUNING_LOG.md`.

Budgets that still hold: under 400 draw calls and under 250 active meshes (the ceiling), keyboard to attack state under 80 ms. The regression also holds each of the six places to a tighter guard of 20 to 48 draws and at most 52 active meshes (`draw_budget_per_place`); that is the number a change is most likely to trip.

Some probes overwrite committed screenshots in `tuning/` as a side effect (`env-probe.mjs` rewrites `s17-env-b1.jpg` to `s17-env-b6.jpg`, `ai-probe.mjs` rewrites `s5-tell.jpg`). Run `git checkout -- tuning/` after a probe unless you mean to replace those pictures, so they do not slip into a commit.

## Before you open a PR

```bash
npm ci
npm run build:engine
npm run regression
```

`npm run regression` drives headless Chrome (set `CHROME=/path/to/chrome` if it is not found) and exits non-zero on any failure. CI runs the same three commands (`.github/workflows/test.yml`) and the Pages deploy waits for them. Put new checks in `tools/regression.mjs`. `node tools/regression.mjs --only <part of a name>` runs just those tests while you work. A test fails if the page logs an error (an uncaught exception, `console.error`, a failed request) while it runs; if a test provokes one on purpose, list the message for that test in `EXPECTED_ERRORS` with the reason. A test that never reaches its state fails after its bound (`__until`) or after 120 s instead of hanging, and the result is written to `regression-result.json`.

## Dependencies

Dependabot owns dependency bumps (`.github/dependabot.yml`). Do not open version-bump or audit PRs by hand, and do not run a scheduled agent that does the same job. Every dependency here is a dev dependency (the page loads none of them), so an advisory is about the QA tooling, not the game.

`package.json` has three `overrides`, kept so `npm audit` stays clean for the transitive dependencies of `lighthouse` and `@axe-core/cli`. JSON cannot carry comments, so the reasons are here:

| Override | Why |
| --- | --- |
| `minimatch` ^11.0.1 | GHSA-g3hv-75wg-m249 |
| `basic-ftp` ^6.2.5 | GHSA-c475-qrg2-pj4r |
| `glob` ^14.0.3 | GHSA-3g3m-2fjr-6pw4 |

Remove an override when the package that pulled in the old version no longer does. A new override needs its advisory number in this table.

## Pull requests

- One change per commit; the measured result goes in the commit message. Commits end with the attribution line your tooling adds.
- A PR body has a short summary and a verification table (commands and results). Say what you did not check.
- Never merge your own PR. The maintainer says "Merge it".
- No telemetry, no accounts, no network calls from the game. Free software only.
- Local only: the playtest log (`sublevel-log`) never leaves the browser.
